# Job Matcher AI - AI Agent Guide

This guide is designed for future AI coding agents working on the **Job Matcher AI** browser extension. It outlines the architecture, key design decisions, known gotchas, and guidelines to maintain security and compatibility with Firefox Add-ons (AMO).

---

## 1. Directory Structure

- `src/manifest.json`: WebExtension manifest (Manifest V3).
- `src/background/service-worker.js`: Background script managing extension state, window events, active tab tracking, and the Gemini API interface.
- `src/background/lib/`: Core backend library modules.
  - `gemini-client.js`: Directly queries Google Gemini API.
  - `prompts.js`: Contains system and user prompts, plus the JSON output schema.
  - `result-parser.js`: Parses model responses and includes a **JSON repair** routine.
  - `cover-letter.js`: Orchestrates resume text, job text resolution, and calls Gemini.
- `src/popup/`: Main extension popup interface (HTML, CSS, JS).
- `src/options/`: Extension configuration options page (HTML, CSS, JS).
- `src/shared/`: Helper functions, types, and constants shared across background and popup contexts.

## 2. Key Architecture & Design Patterns

### 1. Active Web Tab Resolution
- **Problem**: When the popup is opened via `chrome.windows.create`, it is technically a tab itself. A standard `chrome.runtime.sendMessage` from the popup will contain `sender.tab`. If the extension runs scripts on `sender.tab.id`, it will execute inside the empty popup window instead of the target job page.
- **Solution**: The tab resolver checks if the sender's URL starts with the extension's own runtime URL (using `chrome.runtime.getURL("")`). If it does, the extension ignores the sender tab and query-selects the active tab in the last focused normal browser window.
- **Implementation**:
  ```javascript
  const extUrlPrefix = chrome.runtime.getURL("");
  if (sender.tab?.id != null && sender.url && !sender.url.startsWith(extUrlPrefix)) {
    return sender.tab.id;
  }
  ```

### 2. Focus and Window Snapping Constraint
- **Problem**: The popup window is created as a standalone `"popup"` window to prevent it from closing when file upload dialogs or external pages are focused. However, the user needs this window constrained within the active browser window.
- **Solution**: The popup script ([popup.js](../src/popup/popup.js)) polls the coordinates of both the popup window and the active normal browser window (`chrome.windows.getAll`) every 150ms. If the popup's window position extends beyond the main window's bounds, it recalculates the safe coordinates and calls `chrome.windows.update` to snap the window back inside.

### 3. Gemini Token Limits & Thinking Budget
- **Problem**: Models like `gemini-2.5-flash` have "thinking" capabilities. The reasoning tokens generated by the model consume the total output token budget. If `maxOutputTokens` is too low (e.g. `2048`), the model will run out of tokens during its thinking process, resulting in `finishReason: "MAX_TOKENS"` and a truncated/incomplete JSON response.
- **Solution**: Set the default `maxOutputTokens` to `8192` in [gemini-client.js](../src/background/lib/gemini-client.js). This is the maximum allowed limit and provides sufficient buffer.

### 4. Robust JSON Repair and Recovery
- **Problem**: In case the API rate limit, safety blocks, or network issues truncate the JSON response, standard parsing will throw an exception, resulting in a failed match evaluation.
- **Solution**: `repairTruncatedJson` in [result-parser.js](../src/background/lib/result-parser.js) parses the broken string character-by-character to track unclosed quotes, brackets, and curly braces. It auto-closes quotes, appends the closing tags, and provides default fallbacks (e.g., matching score of 1, empty arrays for skills, and a truncated message for reasoning) so the UI remains functional.

## 3. Strict Security & Linting Guidelines

To maintain zero warnings and errors on the Firefox Add-ons linter (`web-ext lint`):
1. **Never use `innerHTML` or `outerHTML`** to inject dynamic variables or content into elements. Doing so triggers `UNSAFE_VAR_ASSIGNMENT` warnings and delays AMO approval.
2. **Use secure DOM manipulation APIs instead**:
   - `replaceChildren()` to clear old children.
   - `document.createElement()` to create tags.
   - `textContent` to assign text safely.
   - `document.createTextNode()` to append unescaped raw text safely.
